# 前端图表与本地偏好方案对比

## 生效规格版本和章节

- 原基线：V3.3 第 3、17、25.16.7、25.20.7 节
- 新基线：V3.4 第 3、17、25.16.7、25.20.7 节

## 涉及模块

- 前端公共组件和路由
- 行情数据中心
- 股票列表与股票日线详情

## 文档原要求

V3.3 指定 Apache ECharts，并只概括行情主数据和日线管理页面。无敏感偏好允许保存在 localStorage，但未明确侧栏状态和最后访问页面。

## 候选方案

使用 shadcn 官方 Chart 组件及其 Recharts 底层，页面其他控件继续使用 shadcn。把侧栏展开状态、最后访问页面、亮暗模式和配色统一作为无敏感本地偏好保存。

## 对比

- 正确性：两种图表方案都能展示价格序列和水平参考线。shadcn Chart 足以覆盖当前开盘、收盘、支撑和压力线需求。
- 安全性：两种图表方案都只消费后端数据。新增本地偏好不包含 Session、密码、密钥、策略源码或业务数据。
- 可靠性：shadcn Chart 与现有主题变量和 React 组件体系一致，减少主题适配和生命周期代码。ECharts 的复杂金融图能力更强，但当前页面不需要自定义 K 线引擎。
- 复杂度：shadcn Chart 的组件、提示和主题模式与现有项目一致，维护面更小。ECharts 需要单独建立封装和主题桥接。
- 兼容性：shadcn Chart 官方支持当前 React 和 Tailwind 组合。最后页面恢复仍通过现有受保护路由，不绕过认证。
- 可测试性：Recharts 输出可由 Testing Library 验证；本地偏好可以直接模拟 localStorage 和重新挂载。

## 最终决定及原因

采用 shadcn Chart（Recharts）。这是用户明确选择，也更符合当前项目已经全面采用 shadcn 的组件边界。侧栏、最后页面、亮暗模式和配色统一保存到 localStorage，避免重复操作。

## 规格、代码和测试影响

- 先发布 V3.4 并切换当前需求基线。
- 新增 shadcn Chart 和 Recharts 依赖。

- 不需要数据库迁移；不改变后端行情、目标、信号或通知契约。
- 增加列表分页、日线完整分页、图表参考线、主题切换、侧栏恢复和最后页面恢复测试。
