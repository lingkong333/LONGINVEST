# 股票清单数据源降级方案

## 生效规格版本和章节

- 原基线：V3.4 第 2.3、7.2、7.3 节
- 新基线：V3.5 第 2.3、7.2、7.3 节

## 涉及模块

- 数据源路由
- 股票主数据刷新
- 证券清单迁移配置

## 文档原要求

东方财富负责股票主数据，新浪只作为实时行情备用来源。

## 候选方案

东方财富仍为股票清单首选来源。若其全市场清单接口整批不可用，允许使用新浪低频全市场清单补充股票身份；东方财富历史日线、前复权和公司行动边界保持不变。

## 对比

- 正确性：继续单用东方财富会在云出口受限时得到空库；降级方案先核对总数、实收行数和代码唯一性，且每个快照只采用一个来源。
- 安全性：降级使用公开 HTTPS 接口和固定浏览器兼容请求头，不绕过验证码、不伪造指纹、不使用代理池。
- 可靠性：清单和价格能力分别熔断，东方财富清单故障不会阻止其正常的历史日线接口。
- 复杂度：复用现有 Provider 路由、限速、重试和审计边界，只新增新浪清单解析及一条配置迁移。
- 兼容性：股票内部代码、市场和公开查询接口不变，前端无需区分清单来源。
- 可测试性：可分别模拟主源失败、降级成功、缺页、重复代码和总数不一致。

## 最终决定及原因

采用候选方案。真实服务器已确认东方财富历史日线接口正常，但其全市场清单接口对当前云出口返回 502 或空响应；新浪全市场清单正常返回。用能力级降级比尝试规避访问控制更可靠。

## 规格、代码和测试影响

- 发布 V3.5 并切换当前需求基线。
- 新浪 Provider 增加证券清单能力，内部并发固定为 2。
- 东方财富证券清单配置允许失败后切换，其他东方财富独占能力不切换。
- 新增 Provider 配置迁移、清单解析、路由降级和迁移链测试。

## 实际验证结果

待服务器迁移、真实清单刷新和股票详情页验收完成后补充。
