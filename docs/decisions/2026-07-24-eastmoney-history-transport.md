# 东方财富历史日线传输方式

## 生效规格和模块

- 原规格：V3.6 第 3.2、4.3、7、8、25.7、25.19 节。
- 涉及模块：`providers`、`history_backfills` 和部署配置。

## 方案对比

V3.6 规定 Provider 使用 HTTPX，并通过固定浏览器兼容请求头低频访问东方财富。
测试机上的 HTTPX 请求会在返回响应前被东方财富直接断开；增加普通请求头不能
改变 TLS 和 HTTP/2 网络特征，也不能解决容器 DNS 命中不可用边缘节点的问题。

候选方案只把东方财富历史日线切换到 `curl_cffi`：保留原域名和 TLS 校验，使用
浏览器兼容网络特征，并允许启动配置指定东方财富官方解析地址。普通行情、新浪、
限流、重试、熔断、响应大小、内容类型和 Schema 校验均保持不变。

| 维度 | 继续只用 HTTPX | 历史日线专用传输 |
|---|---|---|
| 正确性 | 测试机无法取得日线 | 已取得东方财富完整日线响应 |
| 安全性 | TLS 校验完整 | 同样保留域名和 TLS 校验，不使用代理 |
| 可靠性 | 固定失败 | 两个官方地址隔离单点失败，仍最多重试三次 |
| 复杂度 | 依赖较少 | 增加一个成熟依赖和小型边界适配器 |
| 兼容性 | 现有测试简单 | 公开 Provider 契约和业务数据不变 |
| 可测试性 | 可用 MockTransport | 通过注入会话替身覆盖同样的边界检查 |

## 决定和影响

采用候选方案并先发布 V3.7。它是恢复正式系统采集的最小可行改动，比建设代理、
远程采集端或人工导入更简单，也符合不绕过访问控制的安全边界。

不新增数据库迁移和公开 API。新增依赖、历史日线传输适配器、启动配置和对应测试；
完成后验证单股完整历史、失败重试、全市场任务持续推进和容器健康状态。

## 实际验证结果

实施前验证：测试机 HTTPX 和未指定官方地址的浏览器兼容请求均被断开；指定
东方财富官方解析地址后，同一公开接口成功返回日线 JSON，其中平安银行完整请求
返回 1991-04-03 至 2026-07-24 共 8443 条日线。
