# 东方财富服务器 Chromium 历史日线传输

## 生效规格和模块

- 原规格：V3.7 第 3.2、4.3、25.5、25.7、25.19 节。
- 涉及模块：`providers`、`history_backfills` 和 `bulk-history` 部署配置。

## 方案对比

V3.7 使用 `curl_cffi` 模拟浏览器网络特征并固定东方财富官方源站地址。该方式
曾在测试机成功，但随后同一服务器的所有官方地址均在响应前被断开，不能稳定
支撑全市场任务。普通请求头、DNS 切换和有限重试都不能恢复。

候选方案在服务器 Docker 内运行真实 Chromium，仅替换东方财富历史日线的网络
传输。Provider 契约、限流、重试、能力级熔断、任务和数据库事务保持不变。

| 维度 | V3.7 兼容传输 | 服务器 Chromium |
|---|---|---|
| 完整性 | 当前服务器持续断开 | 单次取得 8458 条完整日线 |
| 部署 | 轻量镜像 | 仅历史 Worker 使用较大专用镜像 |
| 隔离 | 与普通后端共用依赖 | 浏览器资源和队列单独隔离 |
| 合规边界 | 不使用代理和验证码绕过 | 同样禁止，并固定单一低频身份 |
| 业务影响 | 无公开契约变化 | 同样无公开契约和数据库变化 |

## 决定和影响

采用服务器 Chromium 方案并发布 V3.8。不建设本地采集端，不连接管理员电脑，
不引入代理或身份轮换。浏览器依赖只安装到 `bulk-history` 专用镜像，其他服务
维持原镜像。正式部署默认每三秒最多开始一次历史请求，并继续受系统共享限流、
最多三次请求、总截止时间和能力级熔断约束。

## 实际验证

2026-07-24 在目标服务器的官方 Playwright Chromium 容器内直接请求东方财富
公开接口，万科 A（000002）返回 HTTP 200，共 8458 条日线，日期范围为
1991-01-29 至 2026-07-24。验证未使用本地采集端、代理、Cookie 或验证码绕过。
