# 东方财富固定浏览器会话与年度分段

## 生效规格和模块

- 原规格：V3.8 第 3.2、4.3、25.5、25.7、25.19 节。
- 涉及模块：`providers`、`history_backfills` 和 `bulk-history` 部署配置。

## 文档要求

V3.8 要求服务器 Docker 内的真实 Chromium 以固定单一身份低频请求东方财富
历史日线，不使用管理员电脑、代理轮换、设备身份轮换或验证码绕过。原实现直接
导航历史接口，并尝试一次取得完整历史。

## 候选方案与对比

2026-07-27 实测表明，普通无头 Chromium 和只修改 User-Agent 的浏览器均被历史
接口断开。使用官方 Chrome，并统一版本、语言、时区、屏幕、缩放、平台、Client
Hints、自动化标记和 WebGL 后，东方财富官网原生历史请求恢复 HTTP 200。

| 维度 | V3.8 直接接口 | 固定浏览器会话 |
|---|---|---|
| 正确性 | 当前服务器持续断开 | 官网请求和年度不复权请求均成功 |
| 完整性 | 大响应曾成功但不稳定 | 每自然年度小于 460 个交易日，不触发抽样 |
| 安全性 | 目标白名单和 TLS | 保留原保护，不复制本地 Cookie 或登录态 |
| 可靠性 | 无页面会话，易被识别 | 每股先官网预热，后续复用同一会话 |
| 复杂度 | 单请求简单 | Provider 聚合年度分段，传输层管理受限会话 |
| 兼容性 | 公开契约不变 | 公开契约和数据库同样不变 |
| 可测试性 | HTTP 结果易替换 | 分段聚合和会话状态可分别使用替身验证 |

提高官网 `smplmt` 到 10000 或一次请求完整几十年时，上游不返回结果；保留
`smplmt=460` 但使用 `beg=0` 会得到跨多年抽样点，不能作为逐日日线入库。因此
不能只增加浏览器伪装，必须同时采用年度分段。

## 最终决定及影响

采用固定浏览器会话与自然年度分段并发布 V3.9。浏览器环境只参考管理员本地
Chrome 的非敏感公开配置，不读取或复制个人会话数据。每只股票首段由官网页面
原生 K 线标签切换触发，后续分段复用同一服务器会话；全局仍保持三秒限速，任一
分段失败时该股不写入部分数据。

代码增加维护中的 `playwright-stealth` 依赖，并在专用历史 Worker 镜像安装官方
Chrome。只读容器把 Chrome 用户目录放在已有的 `/tmp` 内存盘，容器停止后自动
清除。无数据库迁移、公开接口或生成类型变化。测试覆盖年度边界、分段失败、
会话预热、响应限制、超时、重试和关闭清理。

## 实际验证

2026-07-27 在目标服务器临时隔离容器内使用官方 Chrome 150 和固定桌面身份，
东方财富平安银行页面返回 HTTP 200，页面原生历史请求返回 HTTP 200。把页面
原生请求改为 2025-01-01 至 2025-12-31 的不复权日线后，返回 243 条，首条日期
为 2025-01-02，末条日期为 2025-12-31。同一页面会话内直接请求该年度也返回
相同 243 条数据。验证未使用本地 Cookie、代理或验证码处理。

正式只读 Worker 镜像随后验证了 Chrome 150 可由非 root 用户启动，东方财富个股
页返回 HTTP 200，页面原生日 K 标签切换也能发出历史请求。2026-07-27 最终健康
复位时，服务器出口上的历史接口仍以空连接结束并触发 30 秒保护超时；能力级熔断
保持开启，未启动历史回填任务。隔离容器的成功证明请求流程可行，但不能替代当前
服务器出口恢复后的正式回填验收。
