# 新浪 AKShare 双口径历史回填

## 生效规格和模块

- 原规格：V3.9 第 2.3、7.2、8.1、8.5、25.19 节。
- 涉及模块：`providers`、`daily_data`、`qfq`、`history_backfills`、行情数据页面和 `bulk-history` 部署。

## 文档要求

V3.9 要求东方财富作为未复权和前复权完整历史的唯一正式来源，使用服务器 Chrome
建立官网会话并按自然年度分段。全市场只永久保存未复权日线，前复权只长期保存
监控股票，回测数据临时获取后释放。

## 候选方案与对比

目标服务器上的东方财富行情页面可以打开，但正式历史接口持续出现空连接或超时；
浏览器会话、固定身份、年度分段和源站配置均未形成稳定生产结果。服务器直接使用
AKShare 的新浪 `stock_zh_a_daily` 对沪、深、北三市代表股票能够返回完整未复权
历史，100 只混合样本全部成功。

| 维度 | V3.9 东方财富浏览器历史 | 新浪/AKShare 双口径历史 |
|---|---|---|
| 正确性 | 正式 Worker 当前无法取得稳定历史结果 | 统一接口直接返回未复权和前复权日线 |
| 完整性 | 需要逐年拼接并防止抽样 | 单股一次返回完整窗口，再由系统裁剪日期 |
| 安全性 | 需要维护浏览器身份和页面会话 | 低频公开接口，不复制会话、不绕过验证 |
| 可靠性 | 当前服务器出口连续超时并熔断 | 100 只代表样本全部成功，可按股票隔离失败 |
| 复杂度 | Chrome、页面预热、拦截、年度聚合 | 成熟库适配、统一限速和 DataFrame 契约转换 |
| 兼容性 | 只写未复权历史 | 同一任务补齐未复权与前复权，现有表继续复用 |
| 可测试性 | 页面和网络状态较难稳定替换 | 数据帧加载器可注入，解析、异常和边界可单测 |

全市场历史和回测都需要前复权数据。每次回测临时重复下载既增加上游压力，也无法
让管理员提前看到数据准备状态；长期保存版本化前复权数据集能减少重复请求，并让
任务使用的数据版本可核对。代价是数据库占用增加，但数量仍远小于分钟行情，并可
由现有磁盘 95% 保护和版本清理策略控制。

## 最终决定及影响

发布 V3.10。完整历史未复权和前复权改为新浪/AKShare 主源，东方财富历史保留为
非自动诊断后备；东方财富实时和当日日线不变。历史任务每只股票完成两次受限请求，
两份数据分别通过 `daily_data` 和 `qfq` 的公开服务写入。未复权先提交、前复权后
原子切换；第二步失败时任务失败但未复权不回滚，重试幂等补齐。

前复权早期非正值不修改、不伪造，只允许裁去连续非正前缀，并在任务结果记录实际
起始日和截断数量；有效窗口内部出现非正值、缺日或末日锚点不一致时整只失败。
Provider 对新浪能力实施全局串行和三秒间隔。新增 AKShare 仅进入专用历史 Worker，
并新增数据源路由迁移、前复权公开导入入口、任务结果字段和网页展示。

## 实际验证

实施前基准：目标服务器使用 AKShare 1.18.79 获取 20 只北交所、40 只上交所和
40 只深交所股票的完整未复权历史，100 只全部成功，共 234,887 行；含每只请求后
两秒等待共耗时约 331 秒。

2026-07-27 正式验收：在目标服务器从网页创建沪、深、北三市共 10 只股票的完整
历史回填任务，最终状态为成功，10 只成功、0 只失败。未复权与前复权各写入
41,829 行，共 83,658 行；每只股票两种口径的覆盖日期一致，末日收盘价锚点一致，
每只股票仅有一个当前生效的前复权数据集。最后一次失败项恢复从开始到完成耗时
90 秒，网页依次显示等待分发、抓取、校验、双口径入库和 80%、90%、100% 的实时
进度。相关模块测试、生产前端构建和服务器容器更新均通过。
