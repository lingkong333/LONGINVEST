# 历史回填页面可配置并发决策

## 生效规格版本和章节

- 原基线：V3.12 修订说明、历史回填任务章节
- 新基线：V3.13 修订说明、历史回填任务章节

## 涉及模块

- 历史回填页面与任务契约
- Provider 共享限速和并发控制
- Provider 配置版本迁移

## 文档要求与当前问题

历史回填任务契约和页面原来规定默认并发四、最多八，但 V3.12 又把新浪历史能力
固定为最多四并发。因此页面填写更高数字会被底层静默截断，用户看到的配置与实际
执行不一致，并且固定上限替管理员作出了不必要的资源选择。

## 方案对比

1. 页面和 Provider 继续保留固定上限：实现简单，但上限数字由系统替管理员决定。
2. 只移除页面上限：界面看似可配，底层仍会静默截断，行为不正确。
3. 页面只校验正整数，任务快照把填写值传给历史 Provider 调用：任务填写值真实生效，
   同时继续由500毫秒共享限速控制总体请求启动速度。

## 最终决定及原因

采用方案三。任务并发是管理员对单次回填的资源选择，默认四仅作为初始值，不构成
上限。共享限速、每股独立事务、失败隔离、有限重试和熔断规则保持不变。实时行情和
证券清单不接受任务覆盖。

## 代码、数据和测试影响

- 页面移除固定最大值，保留默认四和正整数校验。
- 历史任务公开契约移除固定上限，并把任务并发值传到 Provider 共享运行状态。
- Provider 数据库配置和其他新浪能力保持不变，不需要数据迁移。
- 在服务器通过相同网页任务路径执行高于四的真实批量验收。
