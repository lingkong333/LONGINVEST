# 轻量 AKShare 历史采集镜像决策

## 生效规格

- 原基线：V3.14、V3.10 历史采集修订说明
- 新基线：V3.15 修订说明

## 当前问题

正式完整历史日线已经通过 AKShare 调用新浪接口，但历史 Worker 仍基于完整 Playwright
镜像并安装 Chrome，单个镜像约 6.3 GB。浏览器不参与当前正式链路，却长期占用磁盘。

## 方案对比

1. 保留浏览器生产镜像：诊断方便，但镜像过大，正式运行携带无用攻击面。
2. 单独运行 AKShare 服务：可以隔离 SDK，但增加网络接口、部署和失败点，没有业务
   收益。
3. 在现有后端基础层增加轻量采集阶段：历史 Worker 直接导入 AKShare SDK，复用后端
   代码和依赖层，不携带浏览器；浏览器依赖仅保留为显式离线诊断选项。

## 决定

采用方案三。AKShare 是 Python SDK，由历史 Worker 进程内直接调用。历史容器继续保持
队列和权限隔离，但不再使用 Playwright 基础镜像、Chrome、共享内存或浏览器传输配置。

## 验收

- 镜像由约 6.3 GB 降至 1.31 GB；镜像内 AKShare 版本为 1.18.79，未安装
  Playwright。
- 真实请求取得浦发银行 2025 年 1 月的 18 条新浪日线，日期范围为 2025-01-02 至
  2025-01-27。
- 完整后端测试 2187 项通过、33 项按条件跳过；七个常驻容器、API 就绪检查和前端
  入口均正常。
- 清理前根磁盘已用 42 GB、可用 15 GB、使用率 74%；清理后已用 36 GB、可用
  22 GB、使用率 63%。当前镜像占 4.526 GB，构建缓存占 5.783 GB，二者均无可回收
  内容。
- PostgreSQL 数据卷约 1.506 GB、Redis 数据卷约 71.24 MB、应用日志卷约 120 MB，
  均已保留。
