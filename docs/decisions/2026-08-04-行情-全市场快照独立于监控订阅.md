# 行情全市场快照独立于监控订阅

## 生效规格与模块

- 原规格：V4.5 第 3 章
- 涉及模块：数据源、日线、实时行情、监控调度、系统状态、前端监控列表

## 对比

V4.5 只规定页面展示执行证据，没有明确快照范围和无订阅时是否执行。当前实现先读取监控订阅，没有订阅就跳过，因此无法独立验证行情模块，也无法为后续新增监控股票提供统一行情基础。

候选方案把盘中快照定义为全市场固定时间截面，监控与信号成为其下游。该方案多抓取一些当前未监控股票，但批量接口能够在较少请求内完成；它消除了订阅为空导致的静默跳过，也使自动和手动验证使用同一流程。原始快照仍只在内存中存在，数据库只保存执行摘要，容量和复杂度可控。

## 决定

发布 V4.6，采用全市场快照先行、监控订阅后消费的方案。每日日线同样使用批量接口，批量大面积失败时禁止退化为数千次单股补抓。

## 影响

增加盘中执行摘要字段和手动触发接口；日线与实时行情增加批量边界测试；前端改为直接读取执行摘要，不再依赖旧行情批次明细。

## 服务器数据源验证补充

2026-08-04 真实服务器复测确认：东方财富全市场截面接口返回 502，新浪批量行情接口返回 403，二者连续失败后均按既有规则熔断。腾讯批量行情接口在同一出口正常返回，并在单次响应中提供当日开盘、最高、最低、当前收盘、成交量和成交额。因此腾讯批量行情正式登记为当日日线第三顺位备用源；它只用于目标交易日与上游行情日期一致的当日日线，不承担历史日线回填。
