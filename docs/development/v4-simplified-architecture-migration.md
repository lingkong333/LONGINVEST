# V4.0 简化架构迁移清单

本清单用于把 V3.15 多队列体系切换到 V4.0。每一步完成后记录执行人、时间、数据库版本、Compose 版本、验证结果和回退点。任何删除动作必须等到备份、核对和观察期全部完成。

## 一、必须保留的数据

- 管理员账号、密码版本、Session 和登录安全记录。
- 系统设置、密钥密文、设置历史、Provider 配置和通知渠道配置。
- 股票主数据、交易日历、监控分组、订阅、持仓及历史。
- 未复权日线、前复权数据集、公司行动、数据修订和质量问题。
- 策略草稿、发布版本、参数、目标版本、复核、信号和判断历史。
- 通知事件、渠道投递、尝试和结果未知记录。
- 回测任务、快照、股票结果、订单、交易和指标。
- 审计、系统告警、已完成任务摘要和仍有诊断价值的短期日志。

迁移脚本必须按实际数据库核对以下表族；名称尚未落地的 V4 新表以最终迁移名称为准，但不得减少对应数据类别：

| 表族 | 必须保留或迁移的表 |
|---|---|
| 用户和配置 | `app_user`、`user_session`、`system_setting`、`system_setting_history`、`secret_value` |
| 股票和日历 | `security`、`security_revision`、`trading_calendar_day`、`trading_session` |
| 监控和持仓 | `watchlist`、`watchlist_item`、`monitor_subscription`、`monitor_subscription_revision`、`user_position`、`user_position_history` |
| 行情和质量 | `quote_cycle`、`quote_cycle_item`、`daily_bar_unadjusted`、`daily_bar_revision`、`daily_data_batch`、`qfq_dataset`、`qfq_refresh_run`、`data_quality_issue`、`provider_run` |
| 策略和目标 | `strategy`、`strategy_draft`、`strategy_draft_revision`、`strategy_version`、`strategy_run`、`target_revision`、`subscription_target_binding`、`target_calculation_run`、`target_review` |
| 信号和通知 | `signal_state`、`signal_evaluation`、`signal_event`、`notification_policy`、`notification_event`、`notification_delivery`、`notification_delivery_attempt` |
| 回测 | `backtest_task`、`backtest_item`、`backtest_order`、`backtest_trade`、`backtest_metric`、`backtest_daily_result` |
| 运维事实 | `job`、`job_run`、`job_item`、`event_outbox`、`system_alert`、`system_alert_occurrence`、`system_alert_action`、`audit_event` |

V4 新增或改造的数据包括 `job` 的租约/检查点字段、Provider 能力配置、Provider 请求预算和使用记录、熔断状态、日线/回填任务内游标及失败清单。废弃的是 Redis/RQ、分发器、看门狗、维护进程、监督进程、独立 Worker、旧 Cron 和相关 Compose 服务；旧任务表在观察期内只是停止写入，不等于立即删除。

## 二、迁移前盘点

- [ ] 记录各业务表行数、最大更新时间和关键唯一键重复数。
- [ ] 记录 `job`、`job_run`、`job_item`、`event_outbox` 的各状态数量及关联业务对象。
- [ ] 记录 Redis/RQ 中队列、计划任务、失败任务、延迟任务和消费者数量。
- [ ] 记录当前 Compose 服务、镜像、卷、内存、磁盘和端口。
- [ ] 生成 PostgreSQL 逻辑备份和数据卷快照，并完成一次可读取校验。
- [ ] 禁止清理 Redis 卷、旧镜像、旧任务表和日志。

## 三、数据库基础迁移

- [ ] 为 `job` 增加 V4 状态、优先级、阶段、租约、围栏令牌、下次执行时间、检查点、进度和安全错误摘要。
- [ ] 新建 Provider 能力配置、每日请求预算、请求使用记录和熔断状态表。
- [ ] 为全市场日线与历史回填建立任务内游标、批次暂存、压缩失败清单和批量写入所需索引。
- [ ] 为通知投递建立可领取时间、租约和幂等约束。
- [ ] 保持旧表可读；新代码不得再向旧 `job_run`、通用 `job_item` 和 `event_outbox` 写入。
- [ ] 在生产数据副本上验证迁移前进、回退和再次前进。

## 四、未完成任务处理

- [ ] 先冻结旧体系的新任务入口和 Cron，记录冻结时间。
- [ ] 允许能在短时间内安全完成的运行任务结束，再次盘点状态。
- [ ] 将尚未开始且参数完整的任务转换为 V4 `PENDING`，保留原任务 ID 关联、配置快照和幂等键。
- [ ] 将有可靠业务检查点的暂停/运行任务转换为 `PAUSED` 或 `PENDING`，从最后已提交位置继续。
- [ ] 将缺少参数、检查点不可信、仅用于测试或已过业务时效的任务明确标记 `CANCELED`，写明原因并审计。
- [ ] 通知的 `OUTCOME_UNKNOWN` 不得重置为待发送；保留原状态，由用户确认是否补偿。
- [ ] 迁移结果必须满足“旧未完成任务数 = 已迁移 + 已完成 + 明确取消”，不允许静默丢失。

## 五、应用分阶段切换

- [ ] 先部署只读兼容的新 API，确认旧数据和页面可读。
- [ ] 启用 PostgreSQL 任务创建，保持普通后台停止，检查任务与业务事实同事务落库。
- [ ] 启动一个普通后台，依次开放通知、实时行情、当日日线、策略/目标、回测和历史回填。
- [ ] 每开放一个能力，验证正常、空数据、重复提交、非法输入、超时、单项失败、重启恢复和批量写入。
- [ ] 验证全市场当日日线只创建一个业务任务，任务内部失败股票可见且可补齐。
- [ ] 验证每日额度、最小间隔、最大并发和优先预留对手工、自动、重试、探测全部生效。
- [ ] 切换前端任务、健康、Provider 和进度页面到 V4 接口。

## 六、部署收敛验收

- [ ] 停止并禁用 Redis、RQ 分发器、看门狗、维护进程、监督进程和各独立 Worker。
- [ ] 确认常驻组件只有前端、API、普通后台和 PostgreSQL；策略沙箱只在任务期间存在。
- [ ] 确认没有旧消费者、旧 Cron 或重复端口仍可创建或领取任务。
- [ ] 模拟普通后台强制退出，确认租约到期后从检查点恢复且不重复写业务数据。
- [ ] 模拟 Provider 超时、额度耗尽、主源整体失败和部分股票缺失，确认等待、切换和只补缺行为。
- [ ] 对管理员、配置、日线、策略、目标、信号、通知、回测和审计执行迁移前后数量及抽样内容核对。
- [ ] 完成最小模块测试后，在最终集成阶段执行一次全量测试、前端构建、Compose 启动和页面/API 验收。

## 七、观察期与清理

- [ ] 至少完整观察一个交易日和一次 17:00 全市场日线任务。
- [ ] 观察期内保留旧应用镜像、Redis 卷和旧任务表，只允许只读诊断。
- [ ] 核对无丢任务、无重复通知、无超额请求、无批量锁峰值异常后确认切换完成。
- [ ] 另行生成并审核删除清单，才可删除 Redis 卷、旧镜像、旧 Compose 服务和废弃表。
- [ ] 清理后再次备份，并记录最终内存、磁盘、容器和数据库占用。

## 回退条件

出现管理员无法登录、正式数据不一致、任务重复提交、通知重复扩大、请求额度失控、当日日线无法恢复或策略沙箱边界失效时立即停止新后台并回退应用。数据库只允许使用已验证的向下迁移；若已有新业务数据写入，则保留数据库并以前一版兼容读取，不得用旧备份覆盖新业务事实。

## 阶段停止条件和回退点

| 阶段 | 继续条件 | 立即停止条件 | 回退点 |
|---|---|---|---|
| 盘点与备份 | 表数、任务等式、备份校验全部通过 | 任一正式表未识别、备份不可读 | 不做变更，修正盘点或备份 |
| 数据库迁移 | 副本上前进/回退/再前进均通过，旧数据可读 | 约束失败、数据丢失、旧版无法兼容读取 | 已验证的数据库迁移版本 |
| 旧任务转换 | 每个未完成任务都有迁移、完成或取消结论 | 数量等式不成立、通知结果未知被重置 | 冻结时的任务清单和数据库备份 |
| 单后台灰度 | 登录、任务创建、租约恢复和首个能力通过 | 重复任务、重复通知、额度超用、后台循环退出 | 上一版应用和当前兼容数据库 |
| 能力逐项开放 | 当前能力的最小模块验收通过 | 正式数据不一致、故障扩散到其他能力 | 关闭该能力并恢复上一应用版本 |
| Compose 收敛 | 四个常驻组件和无旧消费者得到确认 | 仍有隐藏消费者或关键健康项异常 | 上一版 Compose 和保留镜像/卷 |
| 观察和清理 | 完整交易日及 17:00 任务通过，数据核对一致 | 丢任务、重复写、额度失控或关键告警未解决 | 保留旧资源，不执行清理；必要时回退应用 |
