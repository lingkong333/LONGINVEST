# 全市场当日日线服务器验收记录

验收日期：2026-07-30

环境：测试服务器上的独立 Docker 项目 `longinvest-daily34`。使用独立 PostgreSQL 数据卷、独立后端镜像和独立测试镜像，没有连接或重启线上服务。

## 功能结果

- 一次全市场采集只创建一个 PostgreSQL 任务和一个 `daily_data_batch`。
- 任务内按 Provider 声明的快照、分页、股票分组或单股计划执行，不创建逐股子任务。
- 每组结束后批量暂存并保存任务检查点；重启可从下一组继续。
- 首轮校验后只重试缺失、接口失败或内容无效的股票，再校验并提交。
- 手工重试复用同一个持久任务处理器，不再进入旧的逐股任务队列。
- 当天正式日线按 500 条批量写入；批次出错时二分定位具体坏行，其他行继续提交。
- 上一收盘价按整批读取，不再对每只股票分别查询。
- 旧日线专用工作进程和隔离 Compose 服务已移除，持久任务由普通后台调度进程执行。
- 普通后台启动时检查最近一次有效日线批次至昨日之间的已确认交易日，多个缺失日期只创建一个恢复任务，并按日期从旧到新处理。
- 恢复任务复用同一个冻结全市场范围，不创建逐股子任务；每个日期保存独立批次和检查点，可在安全点暂停并继续。
- 历史日期尚未上市或已经退市的股票直接记录为合理缺失，不发起无效上游请求；当前停牌状态不会错误覆盖过去交易日。
- Provider 最小请求间隔或并发槽暂时占满时在配置的超时内等待，不再误记为上游失败或触发无意义切源。
