# PRD：全市场策略筛选与多时段回测

## 1. 概述

策略模块负责使用已发布策略版本对全市场股票逐股筛选，输出符合条件的股票及四档价格；回测模块只选择筛选产生的候选批次，使用冻结数据进行多时段独立回测。用户可以按生效日期调整或回滚四档价格，并查看完整图表、交易和收益结果。

## 2. 目标

- 将选股、价格计算与交易模拟拆成可独立查看和复用的两个阶段。
- 支持全市场筛选、多时段验证、逐股失败隔离和可恢复执行。
- 保证策略、参数、数据、候选股票、价格变化和回测结果均可审计、可重放。
- 为每只股票、每个时段提供完整交易与收益明细。

## 3. 用户故事

### US-001：创建全市场策略筛选
**描述：** 管理员选择已发布策略版本、参数和多个时段，对全市场股票逐股判断并获得候选股票。

**验收标准：**
- [ ] 一个筛选只创建一个用户可见任务。
- [ ] 冻结策略版本、参数、股票范围、时段和数据版本。
- [ ] 单股失败不阻止其他股票，支持暂停、恢复、停止和失败项重试。
- [ ] 每股每时段只产生四档价格或未命中原因之一。

### US-002：查看和复用候选批次
**描述：** 管理员查看某次筛选的候选股票，并将该不可变批次用于回测。

**验收标准：**
- [ ] 候选批次显示进度、成功、未命中、失败及原因。
- [ ] 支持按股票、时段和状态分页筛选。
- [ ] 批次完成后不可修改，重复提交具有幂等保护。
- [ ] 回测只能选择候选批次，不能提交任意源码。

### US-003：配置有序多时段
**描述：** 管理员配置多组训练期和测试期，用相同策略分别验证不同历史阶段。

**验收标准：**
- [ ] 单时段满足训练结束早于测试开始。
- [ ] 多时段可以重叠，但四个对应日期边界均不得倒退。
- [ ] 前后端均拒绝非法日期和非法排序。
- [ ] 每个时段独立计算四档价格和回测结果。

### US-004：运行多股票独立回测
**描述：** 管理员选择候选批次，以相同初始资金独立模拟每只股票。

**验收标准：**
- [ ] 每只股票独立使用初始资金，不共享资金。
- [ ] 支持启动、暂停、恢复、停止和失败项重试。
- [ ] 相同冻结输入重复运行得到相同结果。
- [ ] 不展示组合收益、组合净值或组合回撤。

### US-005：调整与回滚四档价格
**描述：** 管理员按生效交易日调整四档价格，或恢复历史价格版本，观察后续交易结果变化。

**验收标准：**
- [ ] 四档价格同时提交、均为正数并严格递增。
- [ ] 新版本只影响生效日及之后。
- [ ] 回滚通过创建新版本完成，不覆盖历史。
- [ ] 从最早受影响日期重算，保存原因、操作者和版本关系。

### US-006：查看单股图表与交易结果
**描述：** 管理员查看每只股票每个时段的价格、目标、买卖点和收益。

**验收标准：**
- [ ] 图表显示日线或 K 线、四档价格、买卖点、调整点和回滚点。
- [ ] 支撑位和压力位可拖动，鼠标移入显示日期、OHLC 和当日有效价格。
- [ ] 观察线不改变回测结果。
- [ ] 页面通过桌面浏览器可视和交互验收。

### US-007：查看明细和批次汇总
**描述：** 管理员比较股票与时段的交易效果，识别盈利、亏损和风险。

**验收标准：**
- [ ] 每股每时段输出交易次数、盈亏金额、收益率、胜率、回撤和持有期指标。
- [ ] 提供订单、成交、持仓和每日权益明细。
- [ ] 批次提供完成情况及收益、回撤、胜率、交易次数分布。
- [ ] 大结果集使用服务端分页、筛选和稳定排序。

## 4. 功能要求

- FR-1：系统必须使用已发布策略版本逐股执行全市场筛选。
- FR-2：系统必须将筛选结果保存为不可变候选批次。
- FR-3：系统必须阻止回测接口提交任意策略源码。
- FR-4：系统必须校验每个训练期与测试期的内部顺序。
- FR-5：系统必须校验多个时段的对应日期边界不倒退。
- FR-6：系统必须为每只股票和每个时段独立计算四档价格。
- FR-7：系统必须为每只股票使用独立初始资金进行交易模拟。
- FR-8：系统必须将用户价格调整保存为按交易日生效的新版本。
- FR-9：系统必须通过创建新版本完成价格回滚。
- FR-10：系统必须从最早受影响日期重新计算后续结果。
- FR-11：系统必须区分用户价格版本与公司行动口径调整。
- FR-12：系统必须提供单股曲线、交易明细、风险指标和批次分布。

## 5. 不做内容

- 不支持所有股票共享资金的组合回测。
- 不在回测模块编写、修改或临时执行策略代码。
- 不根据测试期收益自动优化策略参数或四档价格。
- 不让支撑位和压力位参与策略、交易、信号或通知判断。
- 不在本阶段提供结果导出。

## 6. 技术与体验约束

- 全市场是一个父任务，内部逐股处理，不拆成数千个顶层任务。
- 长任务使用 PostgreSQL 持久状态，具备幂等、检查点和失败隔离。
- 金额与价格使用精确数值；不可变历史承担审计和确定性重放。
- 列表、明细和图表数据按需分页或分段加载。
- 前端复用现有 shadcn/ui 和图表组件，明确加载、空数据、失败和恢复状态。

## 7. 成功标准

- 全市场筛选能够在单股失败时继续并形成可用候选批次。
- 多时段非法顺序无法提交，合法交叉时段可以独立完成。
- 价格调整和回滚不会覆盖历史，重算结果可重复核对。
- 用户可以从批次汇总进入任意股票、时段并核对交易和收益来源。

## 8. 已确认决定

- 全市场逐股执行策略并输出候选批次。
- 回测只能选择策略筛选产生的候选批次。
- 价格调整按指定日期生效，回滚创建新版本。
- 每个时段都包含独立训练期和测试期。
- 多股票使用相同初始资金独立回测，不计算组合收益。
